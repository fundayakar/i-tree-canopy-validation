# i-Tree Canopy Reliability Framework: Proxy Validation and Remote-Sensing Cross-Check

Reproducible analysis package accompanying the manuscript:

> Yakar, F. *Reliability of i-Tree Canopy in Data-Scarce Regions: A Proxy-Sensitivity and Sampling-Precision Framework.* iForest – Biogeosciences and Forestry (under review, ms25/5061).

The package contains two complementary analyses that support the methodological reliability of i-Tree Canopy applications in data-scarce regions:

1. **Quantitative climate-similarity framework** for proxy-region selection.
2. **Independent Sentinel-2 remote-sensing validation** of the i-Tree canopy cover estimate, including point-level validation against the original 20,255 i-Tree sampling locations.

## Part 1: Climate similarity framework

A reproducible quantitative framework for proxy-region selection in i-Tree Canopy applications. Five bioclimatic indicators (mean annual temperature, annual precipitation, temperature seasonality, precipitation seasonality, De Martonne aridity index) are computed from monthly climate normals (1991-2020), z-score standardized across nine candidate cities, and ranked by Euclidean distance from the target city (Ankara).

### Run

```bash
pip install -r requirements.txt
python climate_similarity.py
python plot_pca.py
python plot_ranking.py
```

## Part 2: Sentinel-2 remote-sensing validation

Independent cross-validation of the i-Tree Tree/Shrub canopy estimate using Sentinel-2 multispectral imagery (10 m, spring 2023-2025 median composite), with three complementary methods:

- **Polygon-level binary NDVI thresholding** (multiple thresholds for sensitivity)
- **Sub-pixel fractional cover (FCover)** by NDVI rescaling between bare-soil and dense-canopy endmembers
- **Point-level validation**: NDVI extracted at the 20,034 successfully sampled i-Tree locations (most direct apples-to-apples comparison with i-Tree point sampling)

Cross-checks against ESA WorldCover v200 (2021) and Dynamic World (2023-2025) are also reported.

### Reproduce

1. Run `validation_scripts/parse_kml.py` to extract sampling points from the i-Tree KML export.
2. Run `validation_scripts/derive_polygon.py` to reconstruct the study boundary using an alpha-shape concave hull.
3. Run `validation_scripts/fix_polygon.py` to refine the boundary by excluding lake interior pixels.
4. Upload `validation_data/itree_points.csv` to Google Earth Engine as a FeatureCollection asset.
5. Run `validation_scripts/sentinel2_validation.js` in the Earth Engine Code Editor (update `POINTS_ASSET_PATH` with your asset).
6. Export NDVI, FCover, and RGB rasters to Google Drive (export blocks at the end of the GEE script).
7. Run `validation_scripts/make_validation_figure.py` locally to generate the panel figure.

## Data sources

- **WorldClim v2.1**: monthly climate normals (1991-2020), Fick & Hijmans 2017
- **Sentinel-2 Surface Reflectance**: COPERNICUS/S2_SR_HARMONIZED on Google Earth Engine
- **ESA WorldCover v200**: 10 m global land cover (2021), Zanaga et al. 2022
- **Dynamic World**: near-real-time global 10 m land cover, Brown et al. 2022
